MODULE 03 · 基础

先认识一下：Skill 装在一个文件夹里

以「每日收盘复盘」技能为例

每日复盘技能/

  ├── SKILL.md       ← 核心说明书（必需）

  ├── references/   ← 指标速查（用到才读）

  ├── scripts/       ← 自动拉行情脚本

  ├── assets/        ← 复盘报告模板

  └── 其他文件      ← 随你放

每样东西是干嘛的

SKILL.md = 岗位说明书（必须）
references/ = 员工手册（需要时查阅）
scripts/ = 自动化小工具（自动干活）
assets/ = 素材库（现成模板）

不全塞进 SKILL.md？AI 记忆力有限，像查《公司法》一样，用到才翻。

MODULE 03 · 基础

核心文件 = 「身份信息」+「操作说明」

SKILL.md 长这样

名称：每日收盘复盘

描述：收盘后生成当日复盘，客户问行情时自动使用

步骤：
1. 拉数据：大盘、板块、成交额（注明来源）
2. 看热点：领涨领跌板块
3. 出风险提示
4. 生成复盘报告

红线：数据必须真实，查不到写"未查到"；不给买卖结论（合规）

描述写得好 = AI 才知道何时出手

❌ 差：每日复盘（太短，AI 不知道何时用）

✅ 好：收盘后生成当日复盘，客户问行情时自动使用

description 是技能的「招聘广告」——一句话说清「干什么、何时用」。

开头是「身份信息」（AI 判断何时用），正文是「操作说明」（AI 照着做）。

MODULE 03 · ★
CORE · 四步法 SOP

四步，人人都能建出第一个 Skill

1

选场景 （事不过三）

高频、重复、有标准动作。做好标志：能一句话说清替谁接哪件活。 错误：选偶发任务 / 一个 Skill 包打天下。
2

写 SOP

把「怎么干」写成清晰步骤。做好标志：新人照着做不返工。 错误：写成小作文，有道理没步骤。
3

配输入输出

定义给它什么、要它交什么。做好标志：物料类型、输出模板白纸黑字。 错误：只说「帮我写好点」。
4

测试调优

跑一遍，改到稳。做好标志：连换 3 份材料质量稳定。 错误：跑一次没翻车就定版。
拿高频的活举例（Excel 数据清洗）：① 选场景=每周报表整理，高频重复 ✓ → ② 写SOP=取数 → 清洗 → 透视 → 出图 → ③ 配输入输出=原始 Excel → 清洗后表格+图表 → ④ 测试调优=换 3 类表格试，质量稳定

MODULE 03 · ★
CORE · 好 vs 坏

怎么算好，怎么算坏——建完先对照这页

坏 Skill

  • 名字含糊、描述不清 → AI 不知道何时用（建了不触发的头号原因）
  • 正文堆成小作文，有道理没步骤
  • 只说「帮我写好点」，没输出格式
  • 一个 Skill 塞 N 件事，什么都想干

好 Skill

  • 名字 + 一句描述说清「干什么、何时用」
  • 输入输出明确：给什么、交什么格式
  • 有步骤 SOP，不发散
  • 带 1–2 个真实示例；有边界（不确定就标注，不瞎编）

验收底句：换个人用，也能出同样质量 —— 做得到的是 Skill，做不到的只是你的提示词。

同一个需求，两种写法：坏：名称「投顾助手」，描述「帮我写点好话术」，正文一大段感想 → 又长又没用。 好：名称「客户回访话术」，描述「按客户持仓生成回访话术，回访前使用」，正文=5 步流程 + 红线（不承诺收益）→ 一用就准。

MODULE 03
PITFALLS

什么该建，什么别建

✓

适合建

高频重复、有清晰 SOP、输入输出明确

✕

别建

一次性需求、无规律、靠主观判断或合规拍板

!

别贪多

渐进式加载，10 个半成品不如精做 2-3 个

大同证券场景对号入座：适合建=Excel 数据清洗、周报月报汇总、研报要点提炼（高频、有 SOP）｜别建=一次性专项分析、某客户定制尽调（无规律、靠主观判断）｜先盯 2-3 个最高频场景，做深做稳。

MODULE 03 · ★
CORE · 建后运营

建好只是开始：排错 + 越用越准

排错

建了不触发 / 不好用？

口诀：先改名称和描述，不是往正文堆字。
次序：不触发→改描述；漏步骤→改正文；还错→补真实示例。

迭代

四步环（让 AI 从你的修改里学习）

用 → 改 → 学（让 AI 分析我改了哪、补进 Skill）→ 写回。
好 Skill 是用出来、改出来的。

常见问：要代码吗？不需要。多久建好？简单场景 10–30 分钟。共享？项目级/用户级，或从技能市场、GitHub 直接装别人的来改。

FAQ A · 合规与数据安全

大家最关心的：数据和合规

Q1 客户资料、持仓这些敏感数据会不会泄露？
合规要求大家都懂——真正的风险是习惯性上传。日常文件先脱敏；关键数据走私有化部署，不进公网。—— 合规不是知识问题，是习惯问题。
Q2 用 AI 写的投研 / 投顾内容，合规怎么过？
AI 只是初稿，人必须做审核与签字。—— 责任在人，不在模型。

FAQ · B
FAQ B · 准确性与责任

AI 会出错 / 幻觉，怎么办？

Q1 写错、幻觉了怎么办？
「质量不够」的根因多数不是 AI 笨，是提示词没写清。让 AI 标注【依据来源】、关键场景人工复核，再配合 Skill 把好方法固定下来。原则：AI 是工具，决策和签字的人负责。
Q2 研报 / 数据整理靠不靠谱？
当成辅助，不可当唯一裁判；训练 Skill 时要求输出【风险提示 + 依据】。—— 让模型自己亮出底牌。
